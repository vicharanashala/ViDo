What is OpenSpec?

OpenSpec helps you and a coding agent agree on what a change should do. The agent writes a proposal, testable scenarios and a task list in the repository. You can read and edit that plan before implementation, and a later session can pick up where you left off.

In your agent chat

Ask the agent to explore an idea, then propose a change. Review the scenarios, ask it to apply the agreed tasks, and verify the result. Once the change is ready, archiving records it and updates the project specs. Official quickstart

Use OpenSpec to propose a change to remember my selected calendar view. Include what should happen when I reopen the workspace. Show me the scenarios before implementation.

In your terminal

Use openspec --version to check the CLI. For a new project, run openspec init at its root to configure your coding tools. ViDo already has an OpenSpec workspace. Run openspec list here to see its active changes. Installation guide

Read a real change

Open the archived Firebase authentication change. The proposal explains why sign-in belongs in ViDo. Its spec delta describes what happens when a user dismisses the sign-in dialog. Use that scenario as a review exercise: dismiss the dialog and check the session and route. The design records the implementation choice, and the task list records the work.

Take a change from proposal to archive

  1. From the project root, list active changes and check whether one already covers the request.
  2. For a new feature or UI redesign, align with maintainers in GitHub Discussions. Write the proposal in English, name what is out of scope, and describe observable requirements. Create its proposal, spec delta, design and tasks under openspec/changes/. Use the project’s propose workflow with your coding agent.
  3. Review the scenarios and validate the change. After the change is approved, apply its tasks, exercise the scenarios and record a concise verification summary.
  4. After review, archive the completed change. Inspect the resulting updates under openspec/specs/ and openspec/changes/archive/.

See ViDo’s OpenSpec conventions. With the OpenSpec CLI installed, inspect the specification for this documentation site using:

openspec list --specs
openspec show project-wiki --type spec
openspec validate project-wiki --type spec --strict

For a new change, replace your-change-name with its agreed name. Run the first command when starting work and the second only after implementation and review.

openspec new change your-change-name
openspec archive your-change-name

Review the agent’s evidence

Prompt for your agent

Read the active OpenSpec change. Map each changed requirement to a WHEN/THEN scenario, an implementation file, and a test or manual check. Report missing evidence and the full validation error if validation fails. Leave the change active for my review.

If the CLI cannot find the change, check the working directory and the output of openspec list. If validation fails, inspect the named requirement and its scenario headings. A checked task alone cannot establish that the scenario passes.
