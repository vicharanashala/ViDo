Directory explorer

Follow the placement rules in FOLDER_STRUCTURE.md. Open a folder below for its rules and examples.

src/components/ui/ · Shared primitives

Keep components such as Button, Card, and Badge independent of domain models such as Task and User. Export shared primitives through index.ts and colocate their tests.

src/features/ · Product features

Keep screens and interactions in their owning slice: landing, auth, workspace, teams, or style-lab. Workspace subroute views belong in workspace/views/.

src/data/ · Models, fixtures, and calculations

Keep filters and calculations pure. Anchor sample task dates to Tuesday, 17 November 2026. Examples include sampleTasks.ts and taskFilters.ts.

src/lib/ · User data access

Keep auth request headers and the NestJS user API stores here, never in view components. Tasks use taskStore.ts, calendar events use calendarStore.ts, categories use categoryStore.ts and planning targets use settingsStore.ts. Do not add new Firestore reads or writes.

server/ · Backend service

Place NestJS controllers, services, and DTOs in their feature modules under server/src/. Per-user data lives in the calendar/, categories/, and planning/ modules and the user task files in tasks/, served under /api/user/*. Keep the relational schema in server/prisma/. The events module delivers server-sent updates.

Prompt for your agent

For my requested change, trace the route to the screen, store, and persistence layer. Name the existing files you would edit, the colocated test, and one nearby implementation you can reuse. Explain any new directory before creating it.

Reviewer check. Pick one changed import and follow it. A domain-specific task badge can compose a shared Badge inside the feature. A shared Badge importing Task would couple every consumer to the workspace model.
