Contributing to ViDo Repository structure Working with OpenSpec Working with coding agents

Give the agent a reproducible task

Include the route, whether you used the demo or a signed-in account, the shortest steps, and the result you expected. Ask the agent to read AGENTS.md and its project guides in order. For a planned feature, link the issue or discussion and active OpenSpec change.

Prompt for your agent

Investigate [observed behavior] on [route and mode]. I expected [result] after [steps]. Read the repository instructions and inspect git status first. Reproduce the issue, trace the owning feature and store, and explain the smallest change that fixes it. Preserve unrelated edits. Show the regression check and the result on the other workspace route.

When the result looks wrong

My task appears, then disappears after reload

Record the route first. Preview starts with fixtures. In the signed-in workspace, use a mock account and inspect the request to /api/user/tasks in the browser Network panel. Check the response status and the NestJS terminal, then reload with the same account. The client can fall back to memory after a failed request. Seeing the task once is insufficient evidence of a successful save.

Preview works but sign-in stalls

Check the Auth emulator on port 9099, the project ID and the Vite terminal. Follow local setup to start missing services. Use a mock account. Share the status and error message with the agent and redact tokens and local configuration values.

A test fails after the agent’s fix

Run the failing file in isolation, inspect the first failing assertion and compare it with the intended behavior. Ask for a minimal reproduction before accepting a changed expectation. Run the full suite again after the fix.

npm test -- src/features/workspace/WorkspaceSidebar.test.tsx

Verify before approving

  1. Inspect the branch diff and staged, unstaged, and untracked files. Confirm each change serves the agreed task.
  2. Repeat the original steps yourself. For routing changes try both /preview and /workspace. For private data, try a second mock account.
  3. Run the required checks. Capture the actual result, a screenshot for UI changes, and anything you could not exercise. Keep credentials and personal data out of the PR.

Prompt for your agent

Review this diff against the linked issue. Point to the changed behavior, the test that would fail before the fix, and any assumptions about live versus preview data. Report commands with exit results, manual checks, and unresolved failures. Leave publishing to me.
